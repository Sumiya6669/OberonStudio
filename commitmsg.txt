Четыре раздела панели: СРМ, Бух учет, ИИ, Администрирование

Учёт (миграция 014, схема acc). Управленческий, не налоговый. Двойная запись
с проверкой равенства дебета и кредита при проведении; проведённый документ
неизменяем, ошибка исправляется сторно; проводит только вошедший человек.
Счёт из отработанных часов собирает база, потому что защита от повторного
выставления — это колонка invoiced_in и триггер, а не проверка в браузере.
Счета и оплаты создают черновики проводок; черновик не влияет на отчёты.

Сайт (миграция 015, схема cms). Страницы, блоки и шесть справочников одной
таблицей с описанием полей рядом — интерфейс рисуется по описанию, новый
справочник не требует ни экрана, ни миграции. Пока ничего не опубликовано,
сайт показывает тексты из кода; ошибка сети равнозначна «как было», поэтому
сломать сайт правкой содержимого нельзя. Откат на русский делает база.
История правок только дописывается.

Наблюдение (миграция 016). Живой экран опрашивает базу раз в три секунды
одним вызовом ai_pulse(): шесть запросов в такт дали бы шесть разных мнений
о том, который час. Лента шагов отдаётся с запасом по времени и склеивается
по id — метка времени как курсор молча теряла шаги, потому что строка журнала
получает время начала транзакции, а видимой становится при фиксации.

Найдено и исправлено прогонами, а не чтением:
- core.my_person(): без обёртки security definer агент упирался в
  permission denied for schema auth вместо честного отказа;
- ai_pulse падал целиком из-за сортировки по невыбранной колонке;
- v_agent_board и v_grant_matrix соединялись со ВСЕМИ клиентами и давали
  агенту вторую строку с нулями, выбираемую наугад;
- AiSpend вызывал useMemo после раннего выхода — падение на переходе
  «загрузка -> данные»;
- проводки читаются витриной: связь со счётом составная, а PostgREST
  встраивает только связи по одной колонке.

88 проверок на чистой базе, ноль провалов. Сборка и линтер чисты.
